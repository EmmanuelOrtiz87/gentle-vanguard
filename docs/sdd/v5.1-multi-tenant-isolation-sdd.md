# Software Design Document (SDD) — v5.1: Multi-Tenant Isolation

**Version:** 5.1  
**Date:** July 6, 2026  
**Status:** Draft — EXPLORE phase  
**Stack Baseline:** v3.3.3 (current), targeting v5.1

## 1. Overview

### Purpose

Add multi-tenant isolation to Gentle-Vanguard so multiple projects, teams, or organizations can
share the same orchestrator instance without data leakage, resource contention, or cross-tenant
interference.

### Scope

**Included:**

- Tenant context in session pipeline (session-start, autostart, hooks)
- Isolated `.session/` directories per tenant
- Tenant-scoped Engram memory (namespace isolation)
- Tenant-scoped CodeGraph index (.codegraph/ per tenant)
- Tenant-scoped audit logs
- Tenant-aware dashboard (filtered metrics, per-tenant views)
- RBAC enforcement at tenant boundary

**Excluded:**

- Multi-region/geo-distribution (v6.0)
- Cross-tenant data sharing (explicit opt-in only)
- Tenant self-service portal

### Assumptions

- Tenant ID is injected at session start via env var `GENTLE_TENANT_ID` or autodetected from
  workspace path
- Single host, multi-tenant (not distributed)
- Existing stack components can accept a `-TenantId` parameter
- Engram supports project-scoped isolation (already proven)

## 2. System Architecture

### High-Level Design

```
                  ┌─────────────────────────────────┐
                  │      Orchestrator (shared)       │
                  │  session-start / autostart / cli │
                  └──────────┬──────────────────────┘
                             │ TenantContext.Resolve()
                             ▼
                  ┌─────────────────────────────────┐
                  │        Tenant Router             │
                  │  .session/<tenant_id>/           │
                  │  .codegraph/<tenant_id>/         │
                  │  .telemetry/<tenant_id>/         │
                  └──┬──────────┬──────────┬────────┘
                     │          │          │
                     ▼          ▼          ▼
              ┌──────────┐ ┌────────┐ ┌────────┐
              │  Engine  │ │  MCP   │ │Dashboard│
              │ (tenant) │ │(tenant)│ │(tenant) │
              └──────────┘ └────────┘ └────────┘
```

### Components

#### TenantContext module

- **File:** `src/tenant-context.ts`
- Resolves tenant ID from: `$env:GENTLE_TENANT_ID` > workspace folder name > `tenant-config.json`
- Provides `Get-TenantContext`, `Set-TenantContext`, `Test-TenantIsolation`
- Caches context for session lifetime

#### TenantRouter (path mapper)

- Transforms all session paths: `PathResolver.Get-SessionDir()` → appends `-TenantId`
- All existing components that use `.session/`, `.codegraph/`, `.telemetry/` get transparent routing

#### Tenant-scoped Engram

- Engram already supports `-Project` parameter → map `tenant_id` to project scope
- Add `-TenantId` parameter to all engram scripts for namespace isolation

#### Tenant-aware Dashboard

- Dashboard WS reads tenant from `session-metadata.json` and filters metrics
- `/api/metrics?tenant=<id>` returns scoped data
- UI shows tenant selector when `GENTLE_MULTI_TENANT=true`

### Data Flow

```
Session Start → TenantContext.Resolve() → TenantRouter.MapPaths()
  → session-start-optimized.ps1 uses tenant-scoped paths
  → autostart pipeline uses tenant-scoped config
  → hooks inject tenant context
  → dashboard filters by tenant
```

### APIs/Interfaces

```TypeScript
# Resolve current tenant
Get-TenantContext
# Returns: @{ TenantId = "my-project"; RootDir = "C:\...\.session\my-project"; IsMultiTenant = $true }

# Run command with explicit tenant
Invoke-WithTenant -TenantId "project-a" -ScriptBlock { ... }

# Tenant-scoped engram
mem_save -Project "gentle-vanguard:project-a" -Title "..." -Content "..."
```

## 3. Implementation Plan

### Phase 1: TenantContext core

1. Create `src/tenant-context.ts`
2. Implement `Get-TenantContext`, path resolution, env var detection
3. Update `PathResolver` or equivalent path functions to accept tenant scope

### Phase 2: Session pipeline integration

4. Modify `session-start-optimized.ps1` to detect and propagate tenant
5. Modify `session-autostart.config.json` steps to receive tenant context
6. Add tenant isolation checks in `check-sdd-gate.ps1`

### Phase 3: Component integration

7. Engram: add `-TenantId` to all engram scripts
8. CodeGraph: tenant-scoped `.codegraph/<tenant>/` index
9. Audit pipeline: `audit-pipeline.ps1 -TenantId`
10. Dashboard WS: `/api/metrics?tenant=` filtering
11. Maintenance Watchtower: tenant-scoped health checks

### Phase 4: Verification

12. Integration tests: parallel tenant sessions, no data leakage
13. Security audit: tenant boundary enforcement
14. Performance benchmark: no degradation with 5+ tenants

### Dependencies

- **Internal:** PathResolver, session-start pipeline, engram scripts
- **External:** None (no new dependencies)

### Risks and Mitigations

| Risk                       | Impact   | Mitigation                                                    |
| -------------------------- | -------- | ------------------------------------------------------------- |
| Path collisions            | High     | Centralized TenantRouter, all path resolution goes through it |
| Engram cross-tenant leak   | Critical | Test engram isolation with separate `-Project` scopes         |
| Performance with N tenants | Medium   | Lazy directory creation, shared read-only assets              |
| Dashboard confusion        | Medium   | Clear tenant badge in UI, env flag toggles multi-tenant mode  |

## 4. Acceptance Criteria

- [ ] `Get-TenantContext` returns correct tenant from env var, path, or config
- [ ] Two simultaneous sessions with different tenants produce no file collisions
- [ ] Engram queries from tenant A never return tenant B data
- [ ] Dashboard shows only current tenant metrics by default
- [ ] Audit logs are segregated by tenant
- [ ] Watchtower health check passes for each tenant independently
- [ ] `GENTLE_TENANT_ID` not set → backward-compatible single-tenant mode

## 5. Test Strategy

### Unit Tests

- `tenant-context.tests.ps1`: Resolve from env, path, config, fallback
- `tenant-router.tests.ps1`: Path mapping correctness
- `engram-scope.tests.ps1`: Tenant A cannot read Tenant B data

### Integration Tests

- Parallel session start with different tenants
- Dashboard API with `?tenant=` filter
- Audit log isolation under concurrent load

# Software Design Document (SDD) — v5.1: CI/CD Self-Healing

**Version:** 5.1  
**Date:** July 6, 2026  
**Status:** Draft — EXPLORE phase  
**Stack Baseline:** v3.3.3

## 1. Overview

### Purpose

Implement self-healing capabilities in the CI/CD pipeline so that transient failures (network
flakes, rate limits, dependency conflicts) are automatically retried with backoff, and recurring
failures trigger automatic rollback with incident logging.

### Scope

**Included:**

- Smart retry with exponential backoff + jitter for CI/CD jobs
- Automatic rollback on deployment failure (git revert + re-deploy previous)
- Failure classification: transient vs permanent vs security
- Incident auto-logging to `.session/audit/` + dashboard alert
- Self-healing dashboard section showing recovery actions

**Excluded:**

- Kubernetes-level self-healing (k8s handles pod-level)
- Cross-region failover (v6.0)
- Predictive failure prevention (v6.0 predictive incident response)

### Assumptions

- GitHub Actions workflows defined in `.github/workflows/` (12 active workflows)
- `dashboard-alerts.json` provides alert rule infrastructure
- Audit pipeline (`audit-pipeline.ps1`) provides logging infrastructure
- Rollback scripts exist (`rollback-orchestrator.ps1`)

## 2. System Architecture

### High-Level Design

```
                  ┌──────────────────────────────────────┐
                  │         Self-Healing Controller        │
                  │  ci-self-heal.ps1 (local)             │
                  │  .github/self-heal-action/ (GitHub)   │
                  └──┬──────────┬────────────┬───────────┘
                     │          │            │
                     ▼          ▼            ▼
              ┌──────────┐ ┌────────┐ ┌────────────┐
              │ Retry    │ │Rollback│ │ Incident   │
              │ Engine   │ │Engine  │ │ Logger     │
              │(backoff) │ │(git)   │ │(audit)     │
              └──────────┘ └────────┘ └────────────┘
```

### Components

#### Retry Engine (`scripts/utilities/CI/ci-retry-engine.ps1`)

<!-- REF-OBSOLETA: scripts/utilities/CI/ci-retry-engine.ps1 no tiene equivalente TS (migración PS1→TS) -->

- Retry with exponential backoff: `wait = base * 2^attempt + random(0, jitter)`
- Classifies failures: parse exit code + stderr → TRANSIENT / PERMANENT / SECURITY
- Configurable per-job: `maxRetries`, `baseDelay`, `jitterMax` in `config/ci-self-heal.json`
- Transient: retry up to N times. Permanent: skip retry, trigger rollback. Security: halt + alert.

#### Rollback Engine (`src/multitenant/ci-rollback-engine.ts`)

- On permanent failure in deployment: `git revert HEAD^ --no-edit && git push`
- Re-deploys previous workflow run artifact
- Logs rollback reason, duration, and affected components
- Sends alert via dashboard WS `/api/alerts`

#### Incident Logger (`scripts/utilities/CI/ci-incident-logger.ps1`)

<!-- REF-OBSOLETA: scripts/utilities/CI/ci-incident-logger.ps1 no tiene equivalente TS (migración PS1→TS) -->

- Writes structured incident to `.session/audit/incidents/<timestamp>.json`
- Fields: `failureType`, `job`, `attempts`, `resolution`, `duration`
- Pushes alert to dashboard alerts system

#### GitHub Actions Self-Heal Action (`.github/actions/self-heal/`)

- Composite action that wraps job steps with retry logic
- On failure: calls rollback action + incident logger
- Configurable per workflow via `with: max-retries: 3`

### Data Flow

```
CI Job fails → Retry Engine classifies failure
  → TRANSIENT: retry with backoff (up to N)
  → PERMANENT: Rollback Engine reverts deploy + re-deploys previous
  → SECURITY: Rollback + halt + alert
  → Incident Logger writes to audit + dashboard alert
```

### Configuration (`config/ci-self-heal.json`)

```json
{
  "retry": {
    "maxRetries": 3,
    "baseDelayMs": 5000,
    "jitterMaxMs": 2000,
    "classify": {
      "transientPatterns": ["timeout", "rate limit", "network error", "503"],
      "securityPatterns": ["unauthorized", "forbidden", "invalid token", "CVE-"]
    }
  },
  "rollback": {
    "autoRollback": true,
    "maxRollbackAttempts": 2,
    "notifyChannels": ["dashboard", "audit"]
  }
}
```

## 3. Implementation Plan

### Phase 1: Retry engine

1. Create `config/ci-self-heal.json` with retry/rollback config
2. Implement `ci-retry-engine.ps1` — failure classification + backoff retry
3. Test with simulated transient failures

### Phase 2: Rollback engine

4. Implement `ci-rollback-engine.ps1` — git revert + re-deploy
5. Test rollback on dummy deployment

### Phase 3: Incident logger + alerts

6. Implement `ci-incident-logger.ps1` — audit + dashboard
7. Add alert rule to `config/dashboard-alerts.json`

### Phase 4: GitHub Actions integration

8. Create `.github/actions/self-heal/action.yml`
9. Integrate into 3 key workflows: deploy, release, quality
10. End-to-end test with intentionally broken workflow

## 4. Acceptance Criteria

- [ ] Transient failure retries 3x with exponential backoff
- [ ] Permanent failure triggers automatic git revert
- [ ] Security failure halts pipeline + sends alert
- [ ] Incidents logged to `.session/audit/incidents/`
- [ ] Dashboard shows self-healing events in real-time
- [ ] Config toggle to disable auto-rollback (manual mode)

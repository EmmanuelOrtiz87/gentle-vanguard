# Software Design Document (SDD) — v5.1: Eval/Benchmark + A/B Prompt Testing

**Version:** 5.1  
**Date:** July 6, 2026  
**Status:** Draft — EXPLORE phase  
**Stack Baseline:** v3.3.3 → Multi-tenant isolation (prerequisite)

## 1. Overview

### Purpose

Create a formal evaluation and benchmarking framework for Gentle-Vanguard that measures skill
accuracy, prompt effectiveness, and agent performance. Includes A/B prompt testing to optimize
prompts across tenants and use cases.

### Scope

**Included:**

- Eval runner: execute test suites against skills/agents, collect metrics
- Benchmark registry: versioned results stored in `.session/eval/`
- A/B prompt testing: side-by-side prompt variants, statistical comparison
- Quality gates: eval thresholds that block deployment if below target
- Test suite definition format (YAML/JSON)

**Excluded:**

- Fine-tuning pipeline (exists separately in `scripts/utilities/FINE-TUNING/`)
- Human evaluation workflow (accept/reject UI — future)
- Production traffic A/B (local eval only)

### Assumptions

- Multi-tenant isolation (v5.1 prereq) provides tenant-scoped eval namespaces
- Existing fine-tuning pipeline provides model comparison infrastructure
- Skills expose a standard interface for test harness (Input → Output)

## 2. System Architecture

### High-Level Design

```
                  ┌─────────────────────────────────────┐
                  │         Eval Orchestrator            │
                  │  eval-runner.ps1 / eval-registry.ps1 │
                  └──┬──────────┬────────────┬──────────┘
                     │          │            │
                     ▼          ▼            ▼
              ┌──────────┐ ┌────────┐ ┌────────────┐
              │ Skill    │ │ Prompt │ │ Quality    │
              │ Test     │ │ A/B    │ │ Gates      │
              │ Suites   │ │ Runner │ │ (threshold)│
              └──────────┘ └────────┘ └────────────┘
```

### Components

#### Eval Runner (`scripts/utilities/EVAL/eval-runner.ps1`)

- Loads test suite from `.eval/suites/<skill-name>.json`
- Executes each test case: render prompt → invoke skill → capture output
- Scores output against expected results (exact match, semantic similarity, custom scorer)
- Returns structured results: `@{ suite, cases=[], score, latency, tokens }`

#### Eval Registry (`scripts/utilities/EVAL/eval-registry.ps1`)

- Stores versioned results in `.session/eval/results/<skill>/<timestamp>.json`
- Supports `list`, `compare`, `prune` actions
- Benchmark history for trend analysis

#### A/B Prompt Runner (`scripts/utilities/EVAL/ab-prompt-runner.ps1`)

- Takes two prompt variants (A and B), runs same test suite against both
- Computes delta: `Δ = score(B) - score(A)` with confidence interval
- Outputs recommendation: `PREFER_A`, `PREFER_B`, or `INCONCLUSIVE`

#### Quality Gates (`scripts/utilities/EVAL/eval-quality-gate.ps1`)

- Reads threshold config from `config/eval-gates.json`
- Blocks pipeline step if score < threshold
- Integrates with `session-autostart.config.json` as optional step

### Test Suite Format (`.eval/suites/<name>.json`)

```json
{
  "skill": "codegraph-search",
  "version": "1.0",
  "cases": [
    {
      "id": "search-basic",
      "input": { "query": "auth", "limit": 5 },
      "expected": { "kind": "function", "minResults": 1 },
      "scorer": "contains-kind"
    }
  ],
  "config": {
    "timeout": 30,
    "model": "current"
  }
}
```

### Data Flow

```
User runs eval → EvalRunner loads suite → renders prompts → invokes skill
  → scores output → EvalRegistry stores versioned result
  → (optional) QualityGate compares threshold → PASS/FAIL
```

## 3. Implementation Plan

### Phase 1: Core runner + registry

1. Create `.eval/` directory structure, `.eval/suites/`, `.eval/config.json`
2. Implement `eval-runner.ps1` — load suite, execute, score, store
3. Implement `eval-registry.ps1` — list, compare, prune
4. Create `config/eval-gates.json` with threshold defaults

### Phase 2: A/B prompt testing

5. Implement `ab-prompt-runner.ps1` — side-by-side execution, delta computation
6. Implement prompt variant loader (loads prompt from `.prompts/variants/`)

### Phase 3: Quality gates integration

7. Implement `eval-quality-gate.ps1` — threshold comparison
8. Add optional `eval-run` step to `session-autostart.config.json`

### Phase 4: Test suites for existing skills

9. Create test suites for 10 core skills (codegraph, engram, dashboard, watchtower, etc.)
10. Create benchmark baseline: run all suites → store as v1 benchmark

## 4. Acceptance Criteria

- [ ] `eval-runner.ps1` runs a test suite and returns pass/fail per case
- [ ] `eval-registry.ps1` stores versioned results and supports `compare`
- [ ] `ab-prompt-runner.ps1` compares two prompt variants with statistical delta
- [ ] Quality gate blocks pipeline if score < threshold
- [ ] Existing skills can be tested without modification (standard harness)

# Software Design Document (SDD) — v6.2: Cross-Org Federation

**Version:** 6.2 **Date:** July 7, 2026 **Status:** PROPOSE phase **Prerequisites:** v6.0
cross-workspace mesh, v6.1 AI safety layer

## 1. Overview

### Purpose

Extend the existing cross-workspace mesh (v6.0) to support **multi-organization federation** with
trust boundaries, signed manifests, capability-based authorization, and cross-org audit trails.

### Scope

**Included:**

- Organization registry — org identity, trust anchors, member workspaces
- Signed manifests — workspace manifests signed by org key for non-repudiation
- Cross-org authentication — token-based auth with challenge-response handshake
- Capability-based authorization — workspaces from Org A access only approved capabilities of Org B
- Federation audit trail — all cross-org interactions logged to both orgs
- Dashboard endpoint — `/api/federation` for federation health and status

**Excluded:**

- Real-time cross-org WebSocket (deferred to v7.0)
- Cross-org eval sharing (future)
- Cross-org skill marketplace (deferred)

### Assumptions

- v6.0 cross-workspace mesh provides base discovery and delegation
- v5.1 multi-tenant provides workspace isolation boundaries
- v6.1 safety layer protects against malicious cross-org requests
- Each org has a unique org ID and a key pair (asymmetric) for signing

## 2. System Architecture

### Components

#### 2.1 Org Registry (`scripts/utilities/FEDERATION/org-registry.ps1`)

<!-- REF-OBSOLETA: scripts/utilities/FEDERATION/org-registry.ps1 no tiene equivalente TS (migración PS1→TS) -->

Central registry for organizations known to this workspace. Stores org identity, trust anchors,
approved capabilities, and last handshake timestamp.

**Actions:**

- `register` — add/update an org in the local registry
- `discover` — find orgs via seed or broadcast
- `status` — show all known orgs and their health
- `untrust` — remove an org and invalidate its trust

**Data (`.session/federation/org-registry.json`):**

```json
{
  "localOrg": { "id": "gentle-vanguard", "publicKey": "...", "meshPort": 9091 },
  "knownOrgs": [
    {
      "id": "acme-corp",
      "trusted": true,
      "lastHandshake": "...",
      "approvedCapabilities": ["codegraph-search", "eval-runner"],
      "workspaces": [{ "name": "acme-project", "manifestPath": "..." }]
    }
  ]
}
```

#### 2.2 Federation Auth (`scripts/utilities/FEDERATION/federation-auth.ps1`)

<!-- REF-OBSOLETA: scripts/utilities/FEDERATION/federation-auth.ps1 no tiene equivalente TS (migración PS1→TS) -->

Handles cross-org authentication via signed challenge-response. Each org has an asymmetric key pair;
the public key is the org's identity anchor.

**Actions:**

- `handshake` — initiate cross-org authentication (challenge → signed response)
- `verify` — verify a signed manifest or message from another org
- `token` — generate/validate delegation tokens with expiration
- `keys` — manage local key pair (generate, export, rotate)

**Protocol:**

```
Org A → Org B: "I am org-A, challenge: <nonce>"
Org B → Org A: "I am org-B, signed: <sign(nonce + org-A-id)>"
Org A → Org B: "Verified. Delegating {capabilities} for {duration}"
```

#### 2.3 Extended Cross-Workspace Mesh (update to `cross-workspace-mesh.ps1`)

Adds org-scoped actions to the existing mesh:

- `delegate` — support `-OrgId` parameter for cross-org delegation
- `discover` — filter by org: `-OrgId "acme-corp"` or `-AllOrgs`
- `manifest` — sign manifest with org key before publishing

#### 2.4 Configuration (`config/federation-config.json`)

```json
{
  "version": "1.0",
  "localOrg": {
    "id": "gentle-vanguard",
    "displayName": "Gentle-Vanguard",
    "keyPath": ".session/federation/local-key.pem",
    "defaultMeshPort": 9091
  },
  "discovery": {
    "seedFile": ".session/federation/seeds.json",
    "broadcastEnabled": false,
    "broadcastPort": 9092
  },
  "auth": {
    "tokenExpiryMinutes": 60,
    "maxTokensPerOrg": 10,
    "challengeTimeoutSec": 30,
    "requireSignedManifests": true
  },
  "trust": {
    "newOrgsDefaultTrusted": false,
    "requireAdminApproval": true,
    "autoUntrustAfterHours": 720
  },
  "capabilities": {
    "public": ["codegraph-search", "agent-status"],
    "protected": ["eval-runner", "auto-code-review"],
    "private": ["tenant-config", "safety-policy"]
  }
}
```

### Data Flow

```
Org A discovers Org B via seed file → Org A adds Org B to registry
  → Org A initiates handshake with Org B
    → Challenge-response completes → mutual trust established
  → Org A delegates {capabilities} to Org B for {duration}
  → Org A signs its manifest with org key
  → Org B discovers Org A's signed manifest
  → Org B verifies signature → trusts capabilities listed
  → Cross-org task delegation: Org A requests "code-review" on Org B's workspace
  → Org B checks: is "code-review" in approved capabilities for Org A?
    → Yes: execute task, return result
    → No: deny with "capability not approved"
  → All interactions logged to both orgs' audit trails
```

- [ ] Org registry stores known orgs with trust status
- [ ] Challenge-response handshake completes successfully
- [ ] Signed manifests verified before trust
- [ ] Cross-org delegation respects capability boundaries
- [ ] Untrusted orgs cannot delegate tasks
- [ ] Federation audit log records all cross-org interactions
- [ ] `/api/federation` returns org status, trust count, pending handshakes
- [ ] Key rotation invalidates old tokens

## Common System Archetypes

### 1. Limits to Growth
- **Structure**: Reinforcing growth loop hits a balancing constraint
- **Pattern**: Rapid growth → plateau or decline
- **Intervention**: Weaken the limit, not push growth harder
- **Example**: User acquisition hits market saturation

### 2. Shifting the Burden
- **Structure**: Quick fix (R) undermines fundamental solution (B with delay)
- **Pattern**: Symptom returns, dependency grows
- **Intervention**: Strengthen fundamental solution; use fix as bridge
- **Example**: Overtime instead of process improvement

### 3. Eroding Goals
- **Structure**: Gap between goal and actual → lower goal instead of improve actual
- **Pattern**: Gradual decline in standards
- **Intervention**: Hold goal constant, address the gap directly
- **Example**: "Almost done" becomes the new definition of done

### 4. Escalation
- **Structure**: Two competing R loops where each tries to one-up the other
- **Pattern**: Symmetric acceleration, both sides worse off
- **Intervention**: Unilateral ceasefire or change the rules
- **Example**: Price wars, feature wars

### 5. Success to the Successful
- **Structure**: R loops that allocate more resources to already-successful parts
- **Pattern**: Winner-take-all, concentration, inequality
- **Intervention**: Deliberately redirect resources; change allocation rule
- **Example**: Team that wins → gets more funding → wins more

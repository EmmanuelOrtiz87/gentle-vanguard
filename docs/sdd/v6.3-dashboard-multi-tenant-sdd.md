# Software Design Document (SDD) — v6.3: Dashboard Multi-Tenant

**Version:** 6. **Date:** July 7, 202 **Status:** PROPOSE phas **Prerequisites:** v5.1 multi-tenant
isolation, v6.1 dashboard API extensions

## 1. Overview

### Purpose

Add per-tenant metrics filtering and a tenant selector UI to the existing dashboard (v3.3.2).
Currently the dashboard shows aggregate metrics for the default tenant. With v6.3, users can switch
between tenants and see only that tenant's scoped data.

### Scope

**Included:**

- Tenant selector component in the navigation bar
- Tenant-aware `/api/metrics` endpoint (accepts `?tenantId=` query param)
- Tenant-filtered metrics in `real-data.ts` (reads tenant-scoped `.session/`, `.telemetry/`, etc.)
- Types for tenant dashboard data
- Active tenant indicator in the dashboard header

**Excluded:**

- Tenant management CRUD UI (exists in `tenant-context.ps1` CLI)
- Multi-tenant WebSocket broadcasting (future)
- Tenant-specific alerting (future)

### Assumptions

- v5.1 tenant-context.ps1 provides tenant ID resolution and path mapping
- `session-start-optimized.ps1` exports `GENTLE_TENANT_ID` env var
- `config/tenant-registry.json` lists known tenants
- Dashboard WS server has access to tenant-scoped `.session/` directories

## 2. Architecture

### Components

#### 2.1 TenantSelector (React Component)

Dropdown in the navigation bar showing known tenants from tenant-registry.json. On selection,
updates a query parameter and re-fetches metrics.

**Props:** None (self-contained, reads from `/api/tenants` endpoint)

**Behavior:**

- Fetches tenant list from `/api/tenants` on mount
- Shows current tenant with a colored indicator
- Dropdown with all known tenants + "All Tenants" option
- On change: updates `tenantId` query param → metrics re-fetch with new tenant

#### 2.2 Tenant-Aware Metrics

**`/api/metrics?tenantId=...`**: If tenantId is provided, `real-data.ts` reads from tenant-scoped
paths (e.g., `.session/tenants/<id>/` instead of `.session/`). If omitted, returns aggregate/default
tenant metrics.

**`/api/tenants`**: Returns the list of known tenants from `config/tenant-registry.json`.

#### 2.3 Types (`types/tenant.ts`)

```typescript
interface TenantInfo {
  id: string;
  name: string;
  lastActive: string;
  isDefault: boolean;
}

interface TenantMetrics {
  tenantId: string;
  metrics: DashboardData;
}
```

### Data Flow

```
User opens dashboard → App mounts → TenantSelector fetches /api/tenants
  → Default tenant selected → useMetrics fetches /api/metrics (no tenant param)
  → User selects "project-alpha" from dropdown
  → useMetrics fetches /api/metrics?tenantId=project-alpha
  → Server reads tenant-scoped .session/tenants/project-alpha/... paths
  → Returns filtered metrics → Dashboard re-renders with tenant data
```

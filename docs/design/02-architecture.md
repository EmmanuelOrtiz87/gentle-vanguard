# GV Design System v2 — Architecture

> Technical reference for `packages/gv-design-system/`. Read after `DESIGN.md` (the human-facing design language) and `ADR-0026` (the decision).

**Version**: 2.0.0-alpha.1 · **Last updated**: 2026-09-01

---

## 1. Goals

- **Single source of truth** for all design tokens, components, and tooling in the Gentle-Vanguard ecosystem.
- **Cross-agent accessibility** — opencode, codex, copilot, antigravity, claude code can all read tokens, components, and audit results via MCP.
- **Framework-agnostic CSS core** with adapters for Tailwind v3, Tailwind v4, and plain HTML.
- **Anti-AI-slop by default** — no cream+terracotta, no near-black+acid-green, no bounce easing, no decorative grids except brand signature.
- **Zero breaking changes** for apps already consuming `--gv-*` from `assets/gv-design-system.css` v1. v2 deprecates v1 but does not force migration.

## 3. Token pipeline

### 3.1 Source of truth

`src/tokens/tokens.json` is the **single source of truth**. All other formats are generated or hand-curated derivatives.

```json
{
  "version": "2.0.0",
  "mode": "dark-first",
  "color": { "primary": { "purple": "#a78bfa", "cyan": "#22d3ee" }, ... },
  "typography": { ... },
  "spacing": { ... },
  "radius": { ... },
  ...
}
```

### 3.2 Generated formats

| Format | File | Generated by | Consumer |
| --- | --- | --- | --- |
| CSS custom properties | `src/tokens/tokens.css` | hand-curated (allows comments + organization) | All apps via `@import 'tokens.css'` |
| TypeScript types | `src/tokens/tokens.ts` | hand-curated (allows type exports + BRAND_WAIVERS) | React components + MCP server |
| Tailwind v4 `@theme` | `src/adapters/tailwind.v4.css` | hand-curated (Tailwind v4 syntax) | apps/prompt-studio |
| Tailwind v3 config | `src/adapters/tailwind.v3.cjs` | hand-curated (JS module exports) | apps/web-dashboard |
| Legacy `assets/tokens.v2.json` | (legacy path) | generated by `sync.ts` | backward compat for `src/design/design-tokens.ts` pipeline |

### 3.3 Validation

```bash
npx tsx packages/gv-design-system/src/cli/build-tokens.ts
```

This validates:
- All required top-level keys exist (color, typography, spacing, etc.)
- All hex colors match the `#RRGGBB` pattern
- CSS and TS files exist
- Reports token counts

If `tokens.json` drifts from `tokens.css` / `tokens.ts`, the validator catches it. The hand-curated files are still allowed to add BEM comments, order tokens by importance, etc.

## 4. Component architecture

### 4.1 Pattern: CSS class per component

Every component is a `.tsx` + `.css` pair. The CSS class names are the **public API** of the component (use them in plain HTML, copy them to other frameworks, consume them from Storybook).

```tsx
// Button.tsx
<button className="gv-btn gv-btn--primary gv-btn--md">Save</button>

// Button.css
.gv-btn { ... }
.gv-btn--primary { ... }
.gv-btn--md { ... }
```

This means:
- The same CSS classes work in **plain HTML** (e.g. Design Hub at `apps/design-hub/`).
- The same CSS classes work in **React** (the library).
- The same CSS classes can be **copied** into any other framework (Svelte, Vue, etc).

### 4.2 Token consumption

All components consume tokens via `var(--gv-*)`. They **never** hardcode hex values. This means a token change in `tokens.css` automatically propagates to every component.

```css
.gv-btn {
  background: var(--gv-gradient);  /* ← from tokens.css */
  color: var(--gv-text-inverse);  /* ← from tokens.css */
  border-radius: var(--gv-radius-pill);
}
```

### 4.3 Accessibility (WCAG 2.2)

Every component enforces:
- **Keyboard** — Tab-reachable, `:focus-visible` ring (`outline: 3px solid var(--gv-cyan)`).
- **Screen reader** — `aria-label` on icon-only buttons (TypeScript enforces via interface), `aria-invalid` + `aria-describedby` on form errors.
- **Touch** — minimum 36×36px on desktop, 44×44px on mobile (via `@media (max-width: 640px)`).
- **Reduced motion** — `@media (prefers-reduced-motion: reduce)` collapses all transitions.

### 4.4 Strict TypeScript

Every component has an explicit `interface` for props. Required props are not optional. Forbidden props (e.g. `aria-label` on `IconButton`) are required.

```ts
export interface IconButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: IconButtonVariant;
  size?: IconButtonSize;
  icon: ReactNode;
  'aria-label': string; // ← required, TypeScript will error if missing
}
```

## 5. MCP server

### 5.1 Why MCP?

The stack has 5+ AI agents (opencode, codex, copilot, antigravity, claude code, mavis itself). They all need to:
- Query design tokens ("what's the canonical cyan?")
- Get component APIs ("how do I use Button variant='secondary'?")
- Audit code ("did I introduce any anti-patterns?")
- Sync tokens ("regenerate tokens.css in gv-analytics")

A CLI alone requires a path/args; an MCP server exposes these as standard tool calls, so any agent can invoke them with structured inputs and get structured outputs.

### 5.2 Tools exposed

| Tool | Input | Output |
| --- | --- | --- |
| `list_tokens` | `{ category?, theme? }` | JSON of all tokens or a category |
| `get_component` | `{ name, variant? }` | Source code + props interface + usage example |
| `audit_design` | `{ target, json?, scope? }` | impeccable detect output (human or JSON) |
| `sync_design` | `{ app?, dryRun? }` | Sync output (tokens written, links made) |
| `get_design_md` | (none) | Full DESIGN.md text |
| `list_brand_waivers` | (none) | Object of { rule: { reason, files[] } } |

### 5.3 Transport

stdio (per MCP spec). Launch with:

```bash
npx tsx packages/gv-design-system/src/mcp/server.ts
```

Or register in `config/mcp-registry.json`:

```json
{
  "name": "gv-design-system",
  "type": "user",
  "transport": "stdio",
  "command": "npx",
  "args": ["tsx", "packages/gv-design-system/src/mcp/server.ts"],
  "enabled": true
}
```

### 5.4 Path resolution

The server uses `import.meta.url` + `fileURLToPath` + `dirname` to find the package root. It does NOT use `process.cwd()` (which gives the shell's cwd, not the script's location). This is the lesson learned from the integration: `process.cwd()` returns the repo root when you run `npx tsx packages/gv-design-system/src/mcp/server.ts` from there.

## 6. CLI scripts

### 6.1 `audit.ts`

Wraps `impeccable detect` with stack-friendly output. Same path resolution as the MCP server.

```bash
# Audit a path
npx tsx packages/gv-design-system/src/cli/audit.ts apps/gv-analytics/src

# JSON output for CI
npx tsx packages/gv-design-system/src/cli/audit.ts apps/gv-analytics/src --json

# Specific scope
npx tsx packages/gv-design-system/src/cli/audit.ts apps/gv-analytics/src --scope type
```

Exit codes:
- `0` — clean
- `2` — anti-patterns found (expected, not a failure)
- `1` — real error (impeccable not installed, etc)

### 6.2 `sync.ts`

Regenerates the legacy `assets/tokens.v2.json` (replacement for `assets/tokens.json`) and links the package into consuming apps.

```bash
# Dry run (show what would change)
npx tsx packages/gv-design-system/src/cli/sync.ts --dry-run

# Apply to all consumers
npx tsx packages/gv-design-system/src/cli/sync.ts

# Specific app
npx tsx packages/gv-design-system/src/cli/sync.ts --app gv-analytics
```

The script is idempotent. It writes `assets/tokens.v2.json` only if it differs from the in-memory representation. It uses `pnpm link` (not `npm link`) because the monorepo uses pnpm workspaces.

### 6.3 `build-tokens.ts`

Validates internal consistency of the token files. Not a "build" step in the traditional sense (the CSS is hand-curated, not generated). Just a sanity check.

```bash
npx tsx packages/gv-design-system/src/cli/build-tokens.ts
```

Output:
```
📦 Version: 2.0.0
📦 Mode: dark-first
🎨 Colors: 6 primary, 4 feedback
🔤 Typography: 3 families, 10 sizes
📏 Spacing scale: 13 steps
📐 Radius scale: 8 steps
✅ All token validations passed.
```

## 7. Tailwind adapters

### 7.1 Tailwind v4 (apps/prompt-studio)

`src/adapters/tailwind.v4.css` uses the CSS-first `@theme` directive to map gv-* tokens into Tailwind utility classes.

```css
@import '@gentle-vanguard/design-system/tokens.css';
@import '@gentle-vanguard/design-system/adapters/tailwind.v4.css';

.bg-gv-bg { background: var(--gv-bg); }    /* auto-generated */
.text-gv-cyan { color: var(--gv-cyan); }    /* auto-generated */
.rounded-gv-pill { border-radius: var(--gv-radius-pill); }  /* auto-generated */
```

This means apps using Tailwind v4 can keep their existing utility-class workflow but get the gv-* palette as `bg-gv-*`, `text-gv-*`, etc.

### 7.2 Tailwind v3 (apps/web-dashboard)

`src/adapters/tailwind.v3.cjs` exports a drop-in `theme.extend` config.

```js
// apps/web-dashboard/tailwind.config.js
import { gvDesignSystem, gvColors, gvSpacing } from '@gentle-vanguard/design-system/adapters/tailwind.v3';

export default {
  content: ['./src/**/*.{ts,tsx}'],
  ...gvDesignSystem,  // spreads theme.extend.colors, spacing, radius, etc.
};
```

For web-dashboard, the migration is **additive**: existing `--dash-*` tokens remain (per the "exception" in `docs/brand/UI-STANDARD-ECOSYSTEM.md`), but the bridge adds `gv-*` equivalents. The app can migrate gradually.

## 8. Integration with the stack

### 8.1 MCP registry

`config/mcp-registry.json` declares the server. The mcp-manager (TypeScript) reads this on session start and launches enabled servers.

```json
{
  "name": "gv-design-system",
  "type": "user",
  "transport": "stdio",
  "command": "npx",
  "args": ["tsx", "packages/gv-design-system/src/mcp/server.ts"],
  "enabled": true,
  "autoStart": false
}
```

### 8.2 lefthook pre-commit

`.lefthook.yml` adds a `design-lint` hook that runs `impeccable detect` against staged CSS/TSX files. The hook is non-blocking (`|| true`) by default — it surfaces findings as advisory, not errors. Promote to blocking when the team is ready.

```yaml
design-lint:
  glob: '{apps/*/src/**/*.{css,tsx,jsx},apps/*/style.css,apps/*/*.css,assets/*.css,packages/gv-design-system/src/**/*.{css,tsx}}'
  run: npx impeccable detect --no-config --json --quiet {staged_files} 2>&1 || true
```

### 8.3 Brand waivers

`/.impeccable/config.json` declares waivers for values that are brand signatures:

```json
{
  "detector": {
    "ignoreValues": [
      "inter",
      "Orbitron, 'Rajdhani', 'Share Tech Mono', monospace",
      "JetBrains Mono, 'Cascadia Code', Consolas, monospace",
      "#a78bfa",
      "#22d3ee",
      "#121212",
      "#0a0e17",
      "linear-gradient(135deg, #a78bfa 0%, #22d3ee 100%)"
    ]
  }
}
```

The CLI v4.1.2 reads the **flat** `ignoreValues` array (not the nested `ignoreValues[rule].files[]` schema). For per-line waivers, use inline comments:

```css
/* impeccable-disable gradient-text: brand wordmark "Vanguard" uses intentional gradient per DESIGN.md §2.5 */
.gv-text--gradient { ... }
```

### 8.4 Skill wrapper

`.agents/skills/gv-design-system/SKILL.md` is the cross-tool skill wrapper. Install via `npx skills add` (vercel-labs/agent-skills). Once installed, the skill appears in opencode, codex, copilot, antigravity, claude code, and 12+ other tools.

## 10. Anti-AI-slop enforcement

The DS is opinionated about what NOT to use. These rules are baked into:

1. **The tokens themselves** — no `bounce-easing` token (deleted; DESIGN.md §7.2 documents this).
2. **The CSS classes** — no `cubic-bezier(0.34, 1.56, 0.64, 1)` anywhere in the components.
3. **The audit baseline** — `impeccable detect packages/gv-design-system/src` returns 0 issues. The DS itself is AI-slop-free.
4. **Design Hub** — `apps/design-hub/` demonstrates the correct visual execution. Any new app following the hub should pass the same audit.

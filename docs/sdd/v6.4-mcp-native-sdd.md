# Software Design Document (SDD) — v6.4: MCP Native Integration

**Version:** 6. **Date:** July 7, 202 **Status:** PROPOS **Prerequisites:** v3.3.2 (dashboard), v6.0
(self-evolve), v3.3.3 (watchtower)

## 1. Vision & Problem

### Vision

> MCP (Model Context Protocol) como ciudadano de primera clase en Gentle-Vanguard — no como bridge
> opcional para herramientas externas, sino como el mecanismo NATIVO de extensibilidad.

### Problem Statement

Hoy MCP existe como un bridge custom (`mcp-bridge.ts`) que solo conecta el skill-server interno con
cursor/windsurf/cline. No hay:

- **Estándar**: El bridge es un wrapper JSON-RPC propio, no fully compliant con el protocolo MCP.
- **Extensibilidad**: El usuario no puede conectar sus propios MCP servers (DB local, APIs,
  browser).
- **Discovery**: No hay un registro local de servers MCP disponibles.
- **Gestión**: No hay CLI ni UI para listar, añadir, o monitorear servers MCP.
- **Pipeline**: Los servers MCP no están disponibles como recursos durante sesiones.

### Why Not Marketplace / VS Code

- Marketplace requiere cloud (registro, publish) — viola local-first.
- VS Code Extension embebe GV dentro de otra herramienta — contrario a la visión de workspace
  independiente.
- MCP Native resuelve extensibilidad SIN dependencias externas: el usuario añade servers locales.

### Data Flow

```
User adds MCP server
  → mcp-manager.ps1 register --name sqlite --command "npx @modelcontextprotocol/server-sqlite"
  → Writes to config/mcp-registry.json
  → Gateway picks up on next start / reload
  → Session pipeline spawns server via stdio
  → Dashboard MCP page shows status "running"
  → Agents call tools via Gateway (tools/list, tools/call)
```

### 2.2 MCP Manager (`src/mcp/mcp-manager.ts`)

Actions: `register`, `unregister`, `list`, `start`, `stop`, `restart`, `health`, `reload`

Key design:

- `register` adds a server entry to registry.json
- `list` shows all servers with status
- `start`/`stop` controls server lifecycle (process management)
- `health` pings each server via tools/list
- All servers are local processes (stdio), no cloud dependency

### 2.3 MCP Gateway (`src/mcp-native/mcp-gateway.ts`)

- Reads registry.json on start
- Spawns enabled servers as child processes
- Routes JSON-RPC requests to the correct server based on tool name prefix
- Exposes unified health endpoint (`/api/mcp/servers`)
- Reloads registry on SIGHUP (or explicit reload command)
- Built-in servers: skill-server.ts (existing), engram-mcp (existing)
- User servers: any stdio command the user configures

### 2.4 Dashboard MCP Page (`apps/web-dashboard/src/components/MCPServers.tsx`)

- Table of all registered servers with name, type, status, enabled
- Add button (modal: name, command, args, description)
- Toggle enable/disable
- Start/stop individual servers
- Reload registry

### 2.5 Session Integration

- `config/session-autostart.config.json` gets new step `mcp-gateway-init` (lazy: true)
- Gateway starts at session start, auto-launches enabled servers
- Gateway stops on session end

# Software Design Document (SDD) — v6.1: AI Safety Layer

**Version:** 6.1 **Date:** July 7, 2026 **Status:** PROPOSE phase **Prerequisites:** v6.0 complete
(self-evolving agents, cross-workspace mesh, auto code review, predictive incidents)

## 1. Overview

### Purpose

Add a formal AI Safety Layer to Gentle-Vanguard that constrains, monitors, and audits agent
self-mutations. Existing v6.0 evolution has basic safety (A/B testing, rollback, rate limits) but
lacks structured safety guardrails, prompt injection protection, risk scoring, and human-in-the-loop
escalation.

### Scope

**Included:**

- Safety guardrails framework — formal constraints agent mutations must pass
- Prompt injection protection — sanitize inputs/outputs in agent pipelines
- Mutation risk scoring — rate mutation safety pre-deployment (0.0–1.0)
- Safety audit trail — comprehensive logging of all safety decisions
- Human-in-the-loop approval — escalate high-risk mutations for manual review
- Constitutional AI constraints — hard-coded rules agents cannot mutate or override
- Safety dashboard integration — expose safety metrics via existing dashboard WS

**Excluded:**

- General AGI safety alignment (delegated to v7.0+)
- External red-teaming framework (separate research initiative)
- Formal verification of agent prompts (requires theorem prover)

### Assumptions

- v6.0 self-evolve-engine provides the mutation lifecycle to hook into
- Engram provides persistent storage for safety audit trail
- Dashboard WS provides real-time metrics endpoint
- existing `config/evolution-config.json` can be extended with safety section

## 2. System Architecture

### Components

#### 2.1 Safety Guardrails (`scripts/utilities/SAFETY/safety-guardrails.ps1`)

Central safety engine that validates every mutation against guardrails before deployment.

**Guardrail Types:**

- **Constitutional Rules** — immutable constraints (no self-deletion, no privilege escalation)
- **Blocked Patterns** — regex patterns agents cannot introduce (extended from v6.0)
- **Resource Limits** — max token usage, max file modifications, max network calls
- **Behavioral Bounds** — cannot disable safety systems, cannot mutate other agents without approval

**Interface:**

```powershell
# Validate a proposed mutation against all guardrails
Test-MutationSafety -AgentId "codegraph-search" -ProposedMutation @{ strategy = "prompt-tuning"; changes = @(...) }
# Returns: @{ allowed = $true/false; score = 0.85; violations = @(); riskLevel = "low" }

# Get active guardrails for an agent
Get-AgentGuardrails -AgentId "codegraph-search"
```

#### 2.2 Prompt Injection Guard (`scripts/utilities/SAFETY/prompt-injection-guard.ps1`)

Sanitizes inputs and outputs in agent pipelines to prevent prompt injection, jailbreaking, and data
leakage.

**Detection Methods:**

- **Pattern-based** — known injection patterns (ignore instructions, DAN, etc.)
- **Structural** — embedded code blocks, base64, obfuscated content
- **Entropy-based** — high-entropy strings (potential encoded payloads)

**Interface:**

```powershell
# Scan text for injection attempts
Test-PromptInjection -Text $userInput
# Returns: @{ detected = $true/false; risk = 0.0-1.0; patterns = @(); sanitized = "..." }

# Sanitize text by removing/neutralizing injection vectors
Invoke-PromptSanitization -Text $userInput -Strictness "high"
```

#### 2.3 Mutation Risk Scorer (`scripts/utilities/SAFETY/mutation-safety-scorer.ps1`)

Scores proposed mutations on safety before deployment. Combines multiple signals into a single
safety score.

**Scoring Signals:**

- **Scope Impact** — how many files/agents does the mutation affect?
- **Capability Drift** — does the mutation add capabilities beyond original scope?
- **Pattern Violations** — does the mutation match any blocked patterns?
- **Historical Risk** — has this agent had safety issues before?
- **Similarity to Known Bad Mutations** — cosine similarity with past rollbacks

**Interface:**

```powershell
# Score a mutation's safety
Get-MutationSafetyScore -AgentId "codegraph-search" -Mutation @{ strategy = "skill-composition"; target = "file-system" }
# Returns: @{ score = 0.72; signals = @{ scopeImpact = 0.8; capabilityDrift = 0.3; ... }; riskLevel = "medium" }

# Get scoring configuration
Get-SafetyScoringConfig
```

#### 2.4 Safety Dashboard Integration

Existing dashboard WS exposes safety metrics via `/api/safety`:

- Active guardrails count
- Mutations blocked/allowed today
- Risk score trends per agent
- Pending human approvals
- Recent safety violations

### Data Flow

```
Agent mutation proposed
  → Safety Guardrails: validate constitutional rules + blocked patterns
    → FAIL: block mutation, log violation, alert dashboard
    → PASS: proceed to risk scoring
  → Mutation Risk Scorer: compute safety score
    → score < 0.3: BLOCK + human approval required
    → score 0.3–0.7: AUTO-ESCALATE to human review
    → score > 0.7: AUTO-APPROVE (with A/B test)
  → Prompt Injection Guard: scan mutation payload
    → detected: block, log, alert
    → clean: proceed
  → Deploy mutation (existing v6.0 pipeline)
  → Log all safety decisions to .session/safety/audit/
```

### Phase 3: Mutation Risk Scorer

6. Implement `mutation-safety-scorer.ps1` — multi-signal scoring
7. Implement `Get-MutationSafetyScore`

### Phase 4: Integration

8. Hook safety checks into `self-evolve-engine.ps1` (pre-mutation validation)
9. Create `.session/safety/audit/` directory for safety logs
10. Add `/api/safety` endpoint to dashboard WS
11. Extend `evolution-config.json` with safety integration section

### Phase 5: Verification

12. Test: mutation violating constitutional rule → blocked
13. Test: prompt injection detected → sanitized
14. Test: risk score < 0.3 → blocked + human approval
15. Test: all safety decisions logged to audit

## 4. Acceptance Criteria

- [ ] Mutation that violates constitutional rule is blocked with clear error
- [ ] Prompt injection attempt is detected and sanitized
- [ ] Risk score accurately reflects mutation danger level
- [ ] High-risk mutations (>0.3, <0.7) are auto-escalated to human review
- [ ] All safety decisions are logged to `.session/safety/audit/`
- [ ] Dashboard exposes `/api/safety` with real-time metrics
- [ ] v6.0 self-evolve-engine refuses mutation if safety check fails
- [ ] Blocked patterns from `config/safety-layer.json` are enforced
- [ ] Safety layer can be disabled via config (`global.enabled: false`) for emergency
